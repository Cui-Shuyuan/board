# 04 — 交付面向问题的完整证据单元

依赖：01–03。目标：默认 legacy 的工具返回值直接可用，模型不必从大对象、重复本体说明及审计元信息中重建答案依据。

## 修改入口

`backend/BoardAI.Api/Services/ChatOrchestratorService.cs` 的工具结果组装与序列化；`RulesPlanService` 结果适配；复用 `RuleEvidencePackBuilder` 已修复的身份、绑定和预算算法，但不要直接复制其递归截断投影。

建议抽出共享的正式证据读取/单元构建服务；legacy 按本次查询交付，program 可适配消费。不要强迫 legacy 先建立整次对话大包或重新做 Understand 阶段。

## 工作包 A：证据单元与完整性

证据单元至少具有：规则版本、canonical path、字段/流程范围、正文或结构、关联来源、完整性、内容 hash。证据 ID 稳定对应该实际交付版本，而非任意计数器冒充身份。

按 schema 定义原子单元：定义及其限定、条件与结果、费用及适用范围、完整列表成员、流程节点及必要父约束。允许省掉无关字段；**不允许只保留结论而省掉作用于结论的限制**。

- 无法证明可拆分的 description 整段保留，尤其含否定、例外和回合上限的句子。
- 长字符串不按字符切断再供模型引用；长数组不 `.Take(N)` 后声称完整集合。
- 必需依赖暂未交付时标 partial，并给出缺项与续读引用；partial 证据只能支撑已完整交付的局部事实，不能支持全集/唯一性/无例外的结论。
- 超大不可拆分原子单元返回 `oversized`；可在明确的总预算内进行完整补读，仍超限则说明资料读取限制，不发送截断规则。不要自动扩大整个上下文到无上限。

## 工作包 B：面向模型的薄结果

建议工具响应形态：

```text
query_id / operation / resolved_targets / resolution
evidence: [{id, path, scope, content, completeness}]
relations: 必需的父子、条件或位置关系
unresolved: 真正未解决的指代/范围
omissions / continuations: 本次未交付内容
```

审计侧保留完整评分、导航轨迹、耗时、复用计数；模型侧只保留做当前回答所需字段。不要重复发送中英文同义正文或整个本体树，但若某本体限制实际决定答案，必须作为依赖保留。

同一正文只出现一次，多个查询的绑定单独表达。关系投影不同或参数绑定不同的内容不能只按路径粗暴合并。整个响应按最终序列化字节/字符与模型 token 分别统计，不把字符数当 token 数。

## 工作包 C：按需继续读取

continuation 应由程序生成，绑定规则 snapshot、目标、范围、页位置和投影类型。不得让模型自行构造任意路径或扩大读取范围。读下一页不能导致前页重复消耗唯一正文预算。

先交付本次查询必要单元，额外依赖有界展开。模型确需补充时使用明确的 continuation 或新的语义查询；二者分开计时，避免把程序分页统计为模型重新理解失败。

完整证据与当前会话实际模型可见性一致：历史裁剪后若原文不可见，要重新交付，不能只说“之前读过”。这与 05 的请求账本共同实现。

## 行为测试

- 规则末尾有“不允许”“每回合至多”“除非”时，跨长度阈值前后完整约束不变；无法交付则明确 oversized。
- 列表跨页能重建全集，但第一页不宣称全集。
- 同一证据被两个查询引用，正文只一份、关联都存在。
- 两个参数化实例共享模板但值不同，不错误去重。
- 局部流程包含必要父循环/条件，不引入无关行动格。
- 规则热更新使旧 continuation 失效或继续读取钉住的旧 snapshot，不能混读。
- 序列化后仍满足预算；超限诊断本身不会无限增长。
- 捕获 legacy 实际发给模型的工具消息，断言使用新的交付器；不能只测内部 builder。

## 小规模实验与验收

使用相同冻结查询，比较旧/新工具结果：必要证据覆盖、完整性、正文大小、导航/装配耗时。对大包失败案例再做 Respond-only 控制实验，相同模型配置、多次重复；这个实验只验证交付影响，不代替端到端效果。

目标是让当前大型局部查询明显变小且完整，不能要求每一道题都缩小。若新结果更短但丢掉必要条件，判失败；若更大，应解释增加的必要依据，不能以“覆盖更多”免验收。

通过后在开发集做同轮 legacy 对照。质量明显退步时先定位具体丢失/格式负担，不进入 05 以调度技巧掩盖交付问题。输出适配实现、完整性测试、前后 payload 对照与实际 token/耗时报告。
