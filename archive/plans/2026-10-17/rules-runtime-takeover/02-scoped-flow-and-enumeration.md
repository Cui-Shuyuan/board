# 02 — 实现局部流程与有范围的枚举

依赖：01。目标：程序直接返回用户所问的局部结构，避免模型从整局流程或全概念目录中自行整理。

## 修改入口

`backend/BoardAI.Api/Services/` 下的 `RulesPlanService.cs`、`RulesFlowService.cs`、`RulesConceptCatalog.cs`、`RulesReferenceService.cs`、对应接口及测试。必要时新增小型结构索引服务，复用 `RulesDocumentStore` 的 snapshot 和失效机制。

## 工作包 A：规范结构索引

对 snapshot 建 canonical path 索引，保存父子关系、引用边、节点类型、声明顺序、分支/循环类型和条件。保留原始来源路径。不能继续以局部 id 唯一定位 flow；字符串引用与内嵌对象都须处理，循环引用可检测。

继承 `extends`、参数绑定 `specifies`、实例 `instance_of`、成员集合和任意 description 引用含义不同。先检查仓库 schema 语义，再为受支持的关系建索引；不要把它们全部当作“属于此类别”。

索引键至少包含游戏与规则版本，规则热更新后重新构造；每个请求钉住同一 snapshot，避免请求中途混合新旧规则。

## 工作包 B：局部流程查询

为 flow 增加明确范围，例如：

```json
{"relation":"flow","entity":"<canonical phase path>","scope":"local","include":["children","position","conditions"]}
```

- 有 entity 时先解析再返回目标；不能忽略目标退回整局。
- 整局流程必须显式 `scope=game`；缺省值在工具文档中唯一确定，歧义目标返回候选。
- local 返回目标正文、直接子步骤，以及理解它所必需的父级顺序/循环/触发条件，按需继续读取更深结构。
- 顺序、可选分支、并行、循环、do_after 等按原结构保留；不是所有数组都能译成“先 A 后 B”。
- 同一流程被多个位置引用时返回位置集合；不能任取第一个作为唯一执行位置。
- 对范围不完整的返回附 continuation 和 omissions；不把截取的三个步骤称为完整流程。

验收例：Agricola 喂养查询应包含喂养节点及结算所需局部上下文，不以整局 game 节点作为唯一结果，也不夹带无关行动格。实际依赖由结构确定，禁止给 harvest_feeding 写专用分支。

## 工作包 C：区分目录浏览与语义枚举

工具必须表达两类不同需求，可用不同 relation 或强类型 scope，避免模型猜测：

1. `catalog`：按类型/父范围浏览概念目录，提供分页；用途是发现规则节点。
2. `members`：枚举某个有声明依据的集合或类别成员，提供成员路径和 membership 来源。

枚举优先使用明确集合、slot/子结构及 schema 定义的类型关系。文本中提到某概念只能作为发现线索，不证明全集。

如果现有数据没有可证明的完整成员关系，返回 partial/unsupported 并给出可读取的定义依据。若完整定义明确列出了成员，模型可以根据完整原文回答；程序不需要为一次回答伪造结构化全集。

本阶段只修工具能力，不为了刷过 Wingspan 题临时塞三种栖息地到代码。若发现规则数据普遍缺少成员关系，报告缺口和最小通用 schema 提案；新增内容标准另行评估，不以大规模数据迁移作为本阶段前提。

## 行为测试

- 合成夹具有两个父流程、同名局部 step、分支、循环、字符串 ref 和共享子流程；按完整路径查询互不串位。
- scope=local 只返回目标及必要上下文；scope=game 明确返回整局；无目标局部查询不静默变整局。
- 同一个流程两个父位置都保留；循环引用不会无限展开。
- CatalogPage 分页不丢不重；合法空成员集合与未知全集区别明确。
- 类型继承与实例成员按实际 schema 分开；description 引用不被误当 membership。
- 改规则 snapshot 后索引失效；进行中的请求仍一致。
- 至少两个非 Splendor 真实游戏契约测试，其中包含 Agricola 局部流程和 Wingspan 范围/枚举语义。后者允许揭示数据覆盖不足，不能伪造成功。

## 验收与交付

提交新工具契约、索引/查询实现、测试和冻结查询前后 JSON 对照。合法局部查询不得再出现“目标被忽略”；工具输出所宣称的顺序和全集必须有可指向的来源。

通过 04 的工具结果适配后接入 legacy 聊天，并做小规模同轮冒烟。此时不要求修改 program 状态机，也不以调用数或单个回答漂亮作为完成条件。
