# 规则问答程序接管史诗

日期：2026-10-17。执行对象：DeepSeek V4.1 Flash。状态：待实施。

## 目标与决策

让程序承担规则定位后的导航、正式读取、依赖展开、结果装配、去重、预算和协议检查；模型负责理解用户表达、处理确实需要语义判断的歧义，以及依据正式证据组织简短回答。

本史诗沿着当前默认 **legacy** 路径逐步改进共享工具和编排。保留 program 为实验路径，但不以修复或推广 Understand → 大事实包 → Respond 架构为交付目标。不预设必须两次模型调用，不重新建设第二套规则存储、检索器或通用游戏裁判。

程序接管的衡量标准是：原本需要模型发起的机械性查询和纠错，由可追踪的程序操作完成；正确率不退步，实际等待时间下降。调用次数下降本身不算验收通过。

## 当前事实及其边界

工作基点：`ffac498`，默认配置为 legacy；原始 legacy 提示参考 `a992cfe`。本轮开始时已有两个未跟踪旧计划，须保留。

- 最新 31 题开发诊断：legacy 68.8%，program 37.6%。这是选过失败样本的开发集，不能与此前 133 题实验的百分比直接比较。
- 已修复 canonical path、关系边、绑定复用、预算对账等问题，这些能力应复用。
- `RulesPlanService` 的 `flow` 分支未使用 entity，`list` 返回全目录；后者的 Catalog 未被事实包装配完整消费。
- `RulesFlowService` 目前按局部 id 建位置表，不能据此保证同名局部节点的唯一身份。
- `RuleEvidencePackBuilder.ProjectSource` 会截断字符串；标记 incomplete 不等于截断后的规则可安全用于结论。
- `diagnose_unavailable.py` 会因候选未命中覆盖已装包命中的诊断，现有“23 次 plan/retrieval 失败”不是可靠根因统计。
- Agricola 固定新包成功回答只证明那一次修复有效，不能推出大包策略整体有效。

上述是代码及现有报告支持的观察。模型阅读负担、计划质量、额外推理分别占多少成本，须由本史诗的分阶段实验确认。

## 分工边界

| 工作 | 接管后的责任方 | 边界 |
|---|---|---|
| 从口语识别对象、意图、范围 | 模型 | 程序校验参数和已知身份，不用关键词表假装理解 |
| 精确路径解析、局部流程定位、集合枚举 | 程序 | 数据不支持完整枚举时明确 partial/unsupported |
| 候选正式读取 | 程序 | 读到正式内容不代表已确定该候选就是用户所指 |
| 已声明的依赖、父流程、条件、费用读取 | 程序 | 不把任意文本引用推断为前提或收益 |
| 数值公式求值 | 现有确定性能力 | 只求值受支持公式及已知参数，不猜玩家状态 |
| 合并结果、去重、分页、缓存、预算 | 程序 | 不从规则句子中截半句，不隐瞒缺失 |
| 回答与相关性判断 | 模型 | 引用可读证据，不能把检索分数当规则 |
| 引用、结果类型、调用上限、循环检查 | 程序 | 可验证结构和出处，不能宣称已证明自然语言答案正确 |
| 是否需要澄清 | 模型提出，程序管理出口 | 只补会改变当前答案的必要信息，禁止为清空 pending 反复追问 |

“缺数据”分为规则库未覆盖、预算未读完、用户状态缺失和对象指代不明，四者不能共用一句“信息不足”。已有输入“按四人局摆”不应触发独立人数审问，除非当前问题确实依赖一个与之冲突的状态。

## 统一执行规则

1. 开始前读仓库约定，确认工作区和实际 HEAD。原始日志、QA 留档、未跟踪旧计划不动；不覆盖历史报告。
2. 先写能暴露当前缺陷的行为测试，再实现本阶段。测试应检查结果语义、路径和实际调用，不只检查私有函数存在或提示字符串包含关键词。
3. 先复用 catalog/reference/flow/document snapshot 服务。新建服务只负责清晰职责，不平行复制 program 和 legacy 两套语义。
4. 禁止运行时代码包含某游戏名、某题号、expected path 白名单、针对题面措辞的答案模板。真实游戏节点可以出现在测试；测试必须另有合成异构夹具。
5. 修改工具语义时同步 schema、实际发给模型的提示、测试和文档。无需兼容旧内部协议；API/Android 受影响时同阶段改完并验证。
6. 原 legacy 提示和实验配置冻结保存。新候选提示允许因工具变化而调整，但不得继续冒用原提示 SHA。默认版本只升级到通过对应验收的节点。
7. 没有证据证明效果时报告“未知”；没有运行环境时交付确定性结果及未执行项，不用单测通过代替真实聊天效果。
8. 日志记录耗时、token、工具轨迹、配置指纹。模型返回的 reasoning 仅作可见诊断材料，不能据此精确归因内部思考时间。

## 最终完成条件

- 枚举、局部流程、规范身份、正式读取、依赖展开、分页和请求去重具有跨游戏契约测试。
- 默认候选路径实际使用上述能力，而非只把新服务挂在未启用的 program 分支。
- 模型不再被要求确认程序已经完成的正式读取；真正的指代歧义仍然保留。
- 无“截断规则仍作为完整证据”“Catalog 成功但被丢弃”“无候选就判检索失败”等问题。
- 按计划 06 达到预注册质量和性能门槛。未达到时保留已验证节点，明确未达标能力，不宣称史诗全部完成。
