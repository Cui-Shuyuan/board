## ⚠ 第一版的记账（保留作教训）：14 条"可疑"全是假警报


同日逐条核对结论：**没有一条是动画脚本的错**，三类都是**问题没描述全**造成的。

### 假警报的三种原因（下一版必须修，否则会误导以后的会话）

1. **状态句漏了"我面前的发展区"**（最严重）
   贵族那 4 条（`action.nobles.trigger/choice/repeat`、`action.reserve.intro.001.2`）都被判
   "你面前零张发展卡、贵族不是主动拿的" ✗ —— 而实际脚本里发展区有 9~11 张牌。
   修法：状态句里加"我面前已经买了这些发展卡（按颜色统计 白 N 张 / 红 N 张 …）"。
   （`scripts/_qa_state_probe.py` 里带了这一句的那版，引擎就正确答"允许" ✓）
2. **设置段没有交代"这是按人数取宝石的演示"**
   `setup.gems.*`、`setup.cards.*` 被判"两人局每色只有 4 颗、你放了 7 颗" ✗ —— 引擎说得对，
   但那一段口播正是在演示 4/5/7 三种人数、最后把多余的 3 颗放回盒子。
   修法：设置段的问句加一句"这一段是在演示不同玩家人数的取法，最后会放回盒子只剩 4 颗"。
3. **买牌那一问的价格取成了"无"**（生成器 bug）
   `action.cards.market.001.2`、`action.purchase_reserved.002.1` 被问成"价格为零的发展卡" ✗。
   `describe_action` 里按 `what.bonus` 从源区找卡那一段没找到（和早先步骤级那版同一个地方 ✗），
   于是价格成了 `{}`。修法：直接从 `card_facts.json` 的 `cost_by_template` + 事件里的
   `what`（等级 + bonus）反查，不要扫源区。
   （**脚本本身没问题**：`validate_anim_rules.py` 的「价格−折扣==实付」这两笔都是逐色对上的 ✓）

### 另外记一条**真规则细节**（不是错，但问法要说清）

`action.cards.limit.001.2`/`market.001.3` 被判"手里白二绿一不符合任何合法拿法" ✗ —— 引擎对：
**一次拿取**只能是"三色各一"或"同色两颗"。而脚本里那三颗是"先合法拿过几轮、又付掉一些"的
**剩余**，合法 ✓。修法：状态句要说明这是**累计**结果（"之前拿过 / 又付掉一些，现在是…"）。

## 怎么用好它

- 它擅长：**带状态的规则判断**（手上限、某色在场总数、折扣算法、能不能买）—— 见
  `scripts/_qa_state_probe.py` 的 8 个用例（含 5 个负例，8/8 正确）。
- 它不擅长：**从片段推断完整局面** —— 问题里没说的它不会猜，会直接判"自相矛盾"。
  所以**状态要报全**（发展区/市场/保留区/贵族/各色在场数）。
- 与 `scripts/validate_anim_rules.py` 的分工：那个是**精确算术层**（结构化重放、逐色对账、
  写完脚本立刻跑）；引擎是**独立裁判层**（照规则数据回答，能抓"我理解错规则"）。
