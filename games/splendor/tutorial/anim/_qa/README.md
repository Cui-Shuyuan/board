# 动画合法性问答（手写问题，规则引擎当裁判）

**没有生成器**（用户 2026-09-20 拍板：「不要那个生成器了，由你自己在写脚本时，连带着就把问题一起写了」）。

> **硬规则**：cue 改一次，`qa` 必须跟着改一次。只改 script/events/state/contract、不改问题 = 未完成。旧问题重复问新动作，等于没有校验。

- 问题：优先写在各 cue 的 `qa` 字段（`full.anim.json`）；历史问题仍可在 `questions.json` —— **都手写**，写动画时连脚本一起写
- 问＋记日志：`python3 scripts/qa_anim_ask.py --in <questions.json 或 full.anim.json>`（`--list` 只看问题，`--only cue1,cue2` 只问几条）
- `qa_anim_ask.py` 会自动从 `full.anim.json` 的 `qa` 字段提取问题；它不生成问题。
- 日志：`ask_log_<tag>.md` / `.jsonl`（最新一版是 `ask_log_handwritten.*`）

## 手写问句的五条原则（这轮实测出来的）

1. **一 cue 只问它真正做的那件事**（拿宝石就问拿法；买牌就问该付什么）。
2. **只带判定需要的事实**，不要整桌抄一遍：问拿宝石就带"那堆剩几颗 + 我手上几颗"；
   问买牌就带"价格 + 我面前的折扣 + 我实付了什么"。
3. **不用教程自造词**（"样本/讲解道具"这类引擎不认识，硬问它会跟着瞎推 ✗）。
4. **规则自动发生的事就说成自动**（市场补位、贵族回合结束归属）—— 引擎两次纠过我这条。
5. **没有值得问的就不写**（介绍道具、纯讲解、以及"演示不同人数"的设置段）。

## 效果对比（同一批 cue，两种问法）

| 问法 | 问题数 | 结果 | 单问耗时 |
|---|---|---|---|
| 机器拼的（整桌状态 + 泛泛"有没有违规"） | 21 | 14 通过 / 7 可疑（全是问法问题） | 20~125s |
| **手写（一 cue 一事 + 最小状态）** | **16** | **16 通过 / 0 可疑** | **2~9s（多 ~3s）** |

结论：慢和误判来自"问得太长太泛"，不是引擎慢；**问法是人写的活儿，不该自动化**。
